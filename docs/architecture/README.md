# Architecture diagram

The end-to-end pipeline, from OSM sources to a scored changeset, as one data-flow diagram.

| File | What |
|---|---|
| [`mapguard-pipeline.dataflow.json`](mapguard-pipeline.dataflow.json) | the source: stages, nodes and flows. Edit this, never the HTML. |
| [`mapguard-pipeline.html`](mapguard-pipeline.html) | the interactive diagram, self-contained: open it in a browser for themes, search, focus, path tracing and PNG/SVG export |
| `mapguard-pipeline-light.png`, `mapguard-pipeline-dark.png` | static renders shown in the top-level README |

## Updating it

The HTML is generated by [Archify](https://github.com/tt-a1i/archify) (v2.17). After editing
the JSON:

```bash
node <archify>/bin/archify.mjs validate dataflow docs/architecture/mapguard-pipeline.dataflow.json --quality showcase
node <archify>/bin/archify.mjs deliver  dataflow docs/architecture/mapguard-pipeline.dataflow.json docs/architecture/mapguard-pipeline.html --quality showcase
```

Then refresh the two PNGs. Open the HTML and use **Export → PNG** in light and in dark mode.

## What each node maps to

| Node | Code |
|---|---|
| OSM API 0.6 | [`src/mapguard/data/osm_api.py`](../../src/mapguard/data/osm_api.py), via [`http.PoliteSession`](../../src/mapguard/data/http.py) |
| Planet dump | [`src/mapguard/data/changeset_dump.py`](../../src/mapguard/data/changeset_dump.py) |
| OSMCha | [`src/mapguard/data/osmcha.py`](../../src/mapguard/data/osmcha.py) |
| Ovid labels | [`data/labels/ovid_labels.tsv`](../../data/labels/ovid_labels.tsv) |
| Label miners | [`scripts/mine_changesets.py`](../../scripts/mine_changesets.py), [`scripts/fetch_osmcha_labels.py`](../../scripts/fetch_osmcha_labels.py) |
| Edit fetchers | [`scripts/fetch_osm.py`](../../scripts/fetch_osm.py) (`select`, `changesets`, `versions`, `users`, `histories`); label rules in [`corpora.py`](../../src/mapguard/data/corpora.py) |
| Feature store | [`src/mapguard/features/build_store.py`](../../src/mapguard/features/build_store.py) → `changesets`, `edits` and `user_seq` Parquet tables |
| Release zip | [`scripts/package_release.py`](../../scripts/package_release.py) |
| Hybrid trees | [`train/01_baselines/`](../../train/01_baselines/) |
| Deep MIL model | [`src/mapguard/models/stage2.py`](../../src/mapguard/models/stage2.py), trained by [`train/common/fit.py`](../../train/common/fit.py) |
| Stack + blend | [`train/09_stack/`](../../train/09_stack/), [`train/07_ensemble/`](../../train/07_ensemble/) |
| Scoring | [`train/common/scoring.py`](../../train/common/scoring.py), [`src/mapguard/evaluation/`](../../src/mapguard/evaluation/) |

The diagram leaves out four parts:
- the Overpass geometry fetch for a corpus A subset, because it is measured to add nothing;
- the corpus D replication harvester, which is not in the feature store;
- the research stages 03, 04, 05 and 06.

The top-level README covers all of them.
